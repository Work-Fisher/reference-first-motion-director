# 先出图、后动效工作流

本流程只用于整片职责路由后标记为 `M 动态包装` 或 `G 生成镜头` 的单元。`A 人物`、`E 原生证据` 和 `R 录屏` 不为了形式完整而强行生图。

## 0. 视觉总表门禁

开始当前单元前，必须先读取项目的 `visual-master-plan.md` 并定位对应行。当前单元的覆盖时间、内部切点、职责、主表现形态、本地参考候选、制作层和连续组以该行为准：

- 没有对应行或仍未决定主表现形态：返回整片路由，不凭最近一张图直接生成。
- 当前行与上一行不属于同一连续组：清空上一单元的人物、场景、色调和构图锚点，重新读取当前原文与本地参考。
- 当前行是文字/数字排版：直接生成接近成片的排版结果，精确文字进入 2K 完成图用于审批；最终视频提示词仍遵守固定禁文字/UI尾缀，不能在正文里要求模型复刻这些文字。
- 当前行是文字、数字、标签或真实 UI 主导：参考图中必须已经出现可读的完成态内容，不能把留白或空框当成已经完成的关键视觉。
- 制作中确需改变主表现形态：先更新视觉总表对应行并说明原因，再继续生成。

## 1. 内容诊断

从脚本中只提炼：

- 一句话传播命题。
- 真实信息关系：证据/对比/过程/层级/规模/冲突/揭示。
- 必须出现的主体和精确文字。
- 完成图必须已经兑现的语义：观众在结果稳定态需要看懂什么。
- 不应被视觉化成图标的抽象名词。
- 已选职责与 M01–M10 模式；若没有匹配模式，说明为什么需要新机制。

## 2. 检索与参考契约

先按 [knowledge-map.md](knowledge-map.md) 查看主知识库的原始 GIF、通过版本和对应拆解；再运行增量入口的 `index/search`（有新增时）。查看候选源文件或视频预览后，最多选择 P/C/M 三项。写清借什么、不借什么。

不要写“参考某网站的高级感”。要写到：

```text
P：bed50c362785.mp4 @ 00:00.500，借青蓝紫光在透明介质中折射的色彩行为
C：eef...jpg，借巨字形成空间与中心词尺度，不借绿色
M：9ba...mp4 @ 00:02.000–00:07.000，借散开后回聚的运动规律
不复制：原品牌、Logo、原文案、完整布局、逐帧节奏
```

## 3. 静帧导演卡

```markdown
### 静帧导演卡
- 传播命题：
- 信息关系：
- 画面职责：M / G
- 运动模式：M01–M10 / 新机制；原因：
- 表达层：E1 / E2 / E3；原因：
- P｜色彩/材质：
- C｜构图/字体：
- M｜未来运动依据：
- 色彩锁：主场 / 发光源 / 能量色 / 文字色 / 变化方向
- 成片完成态：结果稳定时已经出现的主体、精确文字/UI与关系
- 2K 交付文件：`*-2K.png`，固定 2048×1152
- 导演句：
- 唯一主角：
- 静态完成图中的精确文字/UI：
- 不复制：
```

导演句应描述一种张力。例如：“内容像被压在黑色空间深处，唯一一束折射光把核心词从表面切开。”不要堆叠“高级、电影感、未来感、震撼”等空词。

## 4. 出图提示词结构

按以下顺序写一条完整提示词：

1. 画幅和唯一主角。
2. 空间关系与尺度。
3. 精确文字/UI、图片内容和它们在完成构图中的尺度、层级与锚点。
4. 光如何产生颜色、颜色经过什么介质。
5. 材质、焦点、边缘和景深。
6. 参考绑定与只借用的机制。
7. 说明不能破坏的关系与主体层级；只有当前案例确有风险时，才补充结构性排除项。

负面约束不要无限增长。若构图仍像信息图，应回到职责、真实关系、运动模式和英雄帧重做，不是在末尾继续补“不要”。

## 5. 单张完成图与 2K 像素验收

默认只做一个 16:9 方向，交付一张 `final-video-reference`。它是用户看到的完成结果图，也是 AI 视频的主体、构图和风格主参考；图中若含可读文字/UI，只借空间锚点和层级，不把这些内容写成视频必须保持项。

英雄帧选择“语义已经兑现、结果稳定可读”的状态。标题模式应看到完整标题与必要标签，流程模式应看到最终结果与已经成立的关系；搭框、空标题位或等待填充的中间态不算完成图。若运动需要从空场开始，在视频提示词的 0 秒状态中描述，不为此额外交付空白图。

- 强参考玩法：保留案例的空间结构、镜头角度、材质、按钮尺度和视觉节奏，在 2K 完成图中替换成当前脚本需要的图片、文字、标签和 UI；不复制品牌、Logo、原文案或身份识别。视频编译时再按固定尾缀处理可读层。
- 生成时把 P/C 对应的实际图片或视频取帧送入图像生成工具；不要只在文字里写文件名。
- 结果文件必须严格为 `2048×1152` PNG。先读取源图真实尺寸；不是该尺寸时，保留源图并用 Lanczos 等高质量重采样输出 `*-2K.png`。
- 放大只解决交付尺寸，不解决语义和细节。文字错误、人物畸变、UI 乱码、主体模糊或构图失败时必须重新生成或定向编辑，再做尺寸验收。
- 以原始细节模式查看最终 2K 文件，确认主体边缘、文字、UI、材质和层级后再展示。
- 输出时先使用 `SKILL.md` 的“全局提示词输出包络”标注原视频/SRT覆盖区间，再展示 2K 图片与视频提示词。
- 若当前环境没有图像生成能力，明确标记为“出图规划稿”，不得说已经生成或达到 2K 验收。

检查：

- 第一眼是否只有一个主角？
- 颜色看起来是否由光/材质/内容产生？
- 是否不必要地出现卡片、图标、数据面板？
- 文字/UI是否真正参与构图，还是像廉价贴纸？
- 完成图是否已经呈现语义兑现后的稳定结果，而非开始态或空占位？
- 最终交付文件是否读取验证为 2048×1152，而不是只在文件名或提示词里写 2K？
- 主体尺度和负空间是否建立了张力？
- 是否能指出它具体学了哪个参考，而不是泛泛相似？
- 是否误抄了参考的品牌识别？

## 6. 反馈闭环

用户不满意时，先把问题归到一个上游变量：

- 命题错
- 表达层错
- 参考职责错
- 色彩行为错
- 英雄帧错
- 文字层级错

一次只改变最主要的一项，并说明变化。完成图通过真实像素验收后保存到当前项目输出目录；同一轮进入时长路由与动态编译。用户明确说“只出图”时才暂停在这里。
