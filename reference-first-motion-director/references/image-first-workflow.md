# 先出图、后动效工作流

本流程只用于整片职责路由后标记为 `M 动态包装` 或 `G 生成镜头` 的单元。`A 人物`、`E 原生证据` 和 `R 录屏` 不为了形式完整而强行生图。

## 0. 视觉总表门禁

开始当前单元前，必须先读取项目的 `visual-master-plan.md` 并定位对应行。当前单元的覆盖时间、内部切点、职责、主表现形态、本地参考候选、制作层和连续组以该行为准：

- 没有对应行或仍未决定主表现形态：返回整片路由，不凭最近一张图直接生成。
- 当前行与上一行不属于同一连续组：清空上一单元的人物、场景、色调和构图锚点，重新读取当前原文与本地参考。
- 当前行是文字/数字排版：图像模型只负责生成无字底板；同时规划精确后期排版与文字运动，不能为了绕开文字禁令改成人物隐喻。
- 当前行是文字、数字、标签或真实 UI 主导：审批对象必须是完成态合成预览，不能把留白底板当成已经完成的关键视觉。
- 制作中确需改变主表现形态：先更新视觉总表对应行并说明原因，再继续生成。

## 1. 内容诊断

从脚本中只提炼：

- 一句话传播命题。
- 真实信息关系：证据/对比/过程/层级/规模/冲突/揭示。
- 必须出现的主体和精确文字。
- 审批时必须已经兑现的语义：观众在结果稳定态需要看懂什么。
- 不应被视觉化成图标的抽象名词。
- 已选职责与 M01–M10 模式；若没有匹配模式，说明为什么需要新机制。

## 2. 检索与参考契约

先按 [knowledge-map.md](knowledge-map.md) 查看主知识库的原始 GIF、通过版本和对应拆解；再运行增量入口的 `index/search`（有新增时）。查看候选源文件或视频预览后，最多选择 P/C/M 三项。写清借什么、不借什么。

不要写“参考某网站的高级感”。要写到：

```text
P：bed50c362785.mp4 @ 00:00.500，借青蓝紫光在透明介质中折射的色彩行为
C：eef...jpg，借巨字形成空间与中心词尺度，不借绿色
M：9ba...mp4 @ 00:02.000–00:07.000，借散开后回聚的运动规律
不复制：原品牌、Logo、原文案、完整布局、逐帧节奏
```

## 3. 静帧导演卡

```markdown
### 静帧导演卡
- 传播命题：
- 信息关系：
- 画面职责：M / G
- 运动模式：M01–M10 / 新机制；原因：
- 表达层：E1 / E2 / E3；原因：
- P｜色彩/材质：
- C｜构图/字体：
- M｜未来运动依据：
- 色彩锁：主场 / 发光源 / 能量色 / 文字色 / 变化方向
- 审批完成态：结果稳定时已经出现的主体、精确文字/UI与关系
- 交付分层：clean-base / final-composite-preview；两层如何对齐
- 导演句：
- 唯一主角：
- 后期可见文字/UI：
- 不复制：
```

导演句应描述一种张力。例如：“内容像被压在黑色空间深处，唯一一束折射光把核心词从表面切开。”不要堆叠“高级、电影感、未来感、震撼”等空词。

## 4. 出图提示词结构

按以下顺序写一条完整提示词：

1. 画幅和唯一主角。
2. 空间关系与尺度。
3. 为后期文字/UI预留的结构、尺度和锚点；精确内容只进入合成预览说明，不进入底板生成提示词。
4. 光如何产生颜色、颜色经过什么介质。
5. 材质、焦点、边缘和景深。
6. 参考绑定与只借用的机制。
7. 说明不能破坏的关系与主体层级；只有当前案例确有风险时，才补充结构性排除项。

负面约束不要无限增长。若构图仍像信息图，应回到职责、真实关系、运动模式和英雄帧重做，不是在末尾继续补“不要”。

## 5. 双层交付与像素验收

默认只评审一个 16:9 方向，但一个方向可能包含两份对齐资产：

- `clean-base`：供图像模型生成、供 H3 作为输入的无字、无 UI 底板。它应保留完成态的空间、光线、材质、主体和排版锚点，只移除必须由后期控制的文字/UI层。
- `final-composite-preview`：在 `clean-base` 上叠加精确标题、数字、标签或真实 UI 的完成态合成预览。只要语义依赖这些后期层，它就是必须交付的审批图。

审批英雄帧默认选择状态机末端的“语义已经兑现、结果稳定可读”状态。标题模式应看到实心落版后的完整标题与必要签名/徽章，流程模式应看到最终结果与已成立的关系；搭框、描边等待填充、空标题位或中间过渡只作为过程设计，不作为默认审批图。只有用户明确要从某个开始态生成时，才把开始态锁为审批端点。

- 没有文字/UI后期层的 M/G 单元，`clean-base` 可以同时承担完成态审批图。
- 同一方向不等于只允许一个文件；需要后期层时，必须成对保存底板与完成态预览，且构图、透视、尺度和光学锚点一致。
- 不把空白底板命名或展示为“完成关键帧”。向用户申请通过时展示 `final-composite-preview`，并同时注明配对的 `clean-base` 是模型输入资产。
- 生成时把 P/C 对应的实际图片或取出的视频帧作为图像参考；不要只在文字里写文件名。
- 两层生成/合成后都必须查看真实像素，再向用户展示。
- 输出最终可复制的静帧/关键帧提示词时，先使用 `SKILL.md` 的“全局提示词输出包络”标注原视频/SRT覆盖区间；时间标头与提示词正文分开。
- 每条最终可复制的静帧/关键帧生成提示词也必须原样追加 `SKILL.md` 的“全局提示词尾注”，并把它作为最后一行。
- 精确文字和真实 UI 不写入生成提示词，只写入合成说明并留给后期合成。
- 若当前环境没有图像生成能力，明确标记为“出图规划稿”，不得说已经生成。

检查：

- 0.5 秒内是否只有一个主角？
- 颜色看起来是否由光/材质/内容产生？
- 是否不必要地出现卡片、图标、数据面板？
- 完成态预览中的文字/UI是否成为构图，还是廉价贴纸？
- 审批图是否已经呈现语义兑现后的稳定结果，而非开始态或空占位？
- `clean-base` 与完成态预览是否严格对齐，移除后期层后仍保留正确锚点？
- 主体尺度和负空间是否建立了张力？
- 是否能指出它具体学了哪个参考，而不是泛泛相似？
- 是否误抄了参考的品牌识别？

## 6. 反馈闭环

用户不满意时，先把问题归到一个上游变量：

- 命题错
- 表达层错
- 参考职责错
- 色彩行为错
- 英雄帧错
- 文字层级错

一次只改变最主要的一项，并说明变化。完成态预览明确通过后，把它与配对的 `clean-base` 一并保存到当前项目输出目录，再进入动态编译。
